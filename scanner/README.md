# 答题卡扫描识别服务（scanner）

把学生作答后的答题卡（扫描仪 300dpi 或手机拍照）转成结构化答案，并按题汇总班级情况。
**纯 OpenCV / NumPy 实现，不下载任何模型，CPU 即可运行，可完全离线。**

本服务是 [answer-sheet-builder](../) 仓库的子目录。制卡端负责排版并导出 `阅卷模板`
（含每个填涂圈的毫米坐标），本服务只认模板 + 图像。

---

## 1. 它能做什么

| 能力 | 说明 |
| --- | --- |
| 选择题识别 | 定位四角定位点 → 透视矫正 → 按模板坐标采样填涂圈 → 判定 A/B/C/D |
| 双输入源 | 扫描仪 300dpi 平面图、手机斜拍图（自带明暗归一化 + 透视矫正） |
| 异常标注 | 每题给出状态：`ok` 正常 / `faint` 浅涂存疑 / `multi` 多涂或难分 / `blank` 未填 |
| 校对图 | 每份卷子回吐一张叠加图，绿圈=已选、红圈=存疑、灰圈=未选，圈旁标注墨迹值 |
| **批量上传** | **一次丢一个班：zip 压缩包 / 整个文件夹 / 一堆散图，按考号自动归组、多页自动合并** |
| **名单匹配** | **上传 `考号,姓名,班级` 名单（CSV/TSV，GBK 也认），自动贴上姓名班级、列出待确认项** |
| 班级统计 | 每题各选项分布 + 正确率；每份卷子得分；一键导出 CSV |
| Web 界面 | 上传模板 → 拖入扫描件 → 看结果 → 出统计，全在浏览器里 |

## 2. 快速开始

### 2.1 Docker（推荐）

```bash
cd scanner
docker compose up -d --build
# 打开 http://<主机IP>:8081
```

默认 `8081` 端口，叠加图落在 `./data/`（compose 已 bind 到容器 `/srv/data`）。

构建默认走清华 PyPI 源，海外或私有源覆盖：

```bash
PIP_INDEX=https://pypi.org/simple docker compose up -d --build
```

### 2.2 本地直跑（开发调试）

```bash
pip install -r requirements.txt
python -m app.server          # http://127.0.0.1:8081
```

### 2.3 自检

```bash
# 全部离线跑，不需要服务、不需要网络、不需要任何外部素材
python tests/test_omr.py        # 识别核心：定位 / 采样 / 判定 / 统计判分
python tests/test_batch.py      # 批量逻辑：路径解析 / zip 解包 / 归组 / 名单匹配 / 页序
python tests/test_service.py    # 服务层：用 Flask 测试客户端直接打接口，不用起服务

# 服务级集成：需要先把服务跑起来
docker compose up -d            # 或 python -m app.server
python tests/e2e_service.py                     # 默认 http://127.0.0.1:8081
BASE=http://192.168.1.10:8081 python tests/e2e_service.py
```

`test_omr.py` 用 `tests/fixtures/` 里 6 份**由真实制卡端渲染出来**的答题卡，跑识别率、
存疑标注与汇总判分；手机拍照图是运行时现场合成的（透视 + 明暗 + 模糊 + 噪声 + JPEG）。
`test_service.py` 把 zip、名单、补录、越界页序这些接线问题在**部署之前**就拦住。
`e2e_service.py` 则对着真容器走一遍完整业务流（含批量上传），容器里是 opencv 4.9。

> 改动识别相关代码后，三份都要跑 —— 尤其 `e2e_service.py`：一个返回 200 的健康探针
> 只能证明进程活着。

素材里刻意埋了两个边界情况：**第 3 题未涂**（应判 `blank`）、**第 8 题用中灰浅涂**（应判 `faint`）——
这两条是判定逻辑最容易退化的地方。素材怎么重新生成见 [../dev/README.md](../dev/README.md)。

## 3. 使用流程

### 3.1 批量模式（一个班，推荐）

```
┌──────────────────┐   ┌──────────────────┐   ┌───────────────────────────────┐
│ 扫描仪 / 手机     │   │ 按考号命名 /     │   │ scanner 服务                   │
│ 扫出 PNG / JPG    │──▶│ 每个学生一个目录  │──▶│ 拖入 zip 或整个文件夹           │
│                  │   │ 打成 zip 也行     │   │  + 名单(CSV)  → 识别 → 匹配     │
└──────────────────┘   └──────────────────┘   └───────────────────────────────┘
                                                       │
                        ┌──────────────────────────────┴──────────────────┐
                        ▼                                                 ▼
              待人工确认队列(补录姓名/班级)                    成绩 CSV（带考号/姓名/班级）
```

1. **制卡端导出模板**并在服务里上传（同 3.2 第 1~2 步）。
2. **整理扫描件**，文件名或目录名里带上考号 —— 见下面的命名约定。
3. **拖入** `② 批量上传` 区域：可以直接拖 zip、拖散图，也可以拖**整个文件夹**（浏览器会自动递归）。
4. **选名单**（可选）：`考号,姓名,班级` 的 CSV/TSV。名单也可以直接放进 zip 里，服务会自己找。
5. **开始批量识别**。页面按考生一位一张卡，显示姓名班级、答案摘要、每面校对图缩略图（点开看原生分辨率）。
6. **处理待确认队列**：考号不在名单里、跨目录重复、页序异常等会列出来，补上姓名/班级后点「重新套用」——
   只改标注，**不会重新识别**，识别出来的答案不会被改动。
7. **出统计 / 导出**：填标准答案 → 统计；`导出成绩 CSV` 带考号/姓名/班级列，`导出名单对账 CSV` 用来核对谁没交。

### 3.2 单张模式（调参、排查用）

1. **制卡端导出模板**：答题卡生成器工具栏点 `🎯 阅卷模板`，得到一个
   `asb-omr-template-A4-20q-20260925-0140.json` 这样的文件。
   > 前提：卷子里有**填涂圈模式**的选择题（不是手写作答模式），否则会提示「没有可识别的填涂圈」。
2. **上传模板**：扫描服务的第 1 步选这个 json，页面会显示题数与面数。
3. **拖入扫描图**：一次可以传多份，逐份识别。
4. **看结果**：左侧是校对图（叠加图），右侧是每题判定表，存疑题带红色标记。
5. **填标准答案**（可选）：`1A 2B 3C` 或 `ABCD` 都行，然后出统计——每题正确率、每份得分。
6. **导出 CSV**：逐题答案矩阵 + 得分列。

> **一个模板 = 一面卷子。** 双面卷请把每一面都扫出来，并在文件名里写清页序
> （`正面.png` / `反面.png` / `_1` `_2` / `第2页`）；批量模式下服务会自动按页序合并。

### 3.3 文件命名约定（批量模式的关键）

**考号从目录名或文件名里取，4~20 位数字。目录名优先。**

| 形式 | 解析结果 |
| --- | --- |
| `2026010234/正面.png` + `2026010234/反面.png` | 考号 `2026010234`，两面自动合并 ✅ 推荐 |
| `2026010234_1.png` `2026010234_2.png` | 考号 `2026010234`，页序 1、2 |
| `张伟明-2026010234.png` | 考号取**最后一段**数字串 |
| `20xx/2026010234.png` | 目录里没有数字 → 回退到文件名取考号 |
| `随机名.png` | 解析不出考号 → **用文件名当标识**，并标记「未能解析出考号」进入待确认队列 |

页序提示认这些写法（大小写不敏感）：`正面/反面`、`前页/后页`、`首页/背页`、`上/下`、
`front/back`、`f/p1`、`r/p2`、`第2页`，以及 `_1` `_2` 这样的裸数字（按「第 N 页」，上限 20 页）。
裸数字在 1~20 之外的不当页号，避免把年份当成页码。

打包时自动忽略：`__MACOSX/`、`._*` 资源分叉文件、`.DS_Store`、`Thumbs.db`、`.git/`。
嵌套 zip 也会被展开。

## 4. 识别流程（`app/omr.py`）

```
原图
 ├─ 灰度化 → 形态学背景除法归一化（压掉手机拍照的明暗渐变）
 ├─ 自适应二值化 → 轮廓筛选
 │    面积 ∈ [0.25·期望, 2.2·期望]，长宽比 0.55~1.8，
 │    实心度 ≥ 0.30，且必须落在页面外侧 22% 边带内
 ├─ 候选点按 x+y / x-y 取极值 → tl, tr, br, bl
 ├─ 自检：四点四边形面积 ≥ 0.35·图幅，否则判为误检
 ├─ getPerspectiveTransform → 矫正到与模板一致的 mm 网格
 │    ★ 目标点是「模板里的定位点坐标」，不是纸张四角（差一个内缩量）
 ├─ 按模板每个填涂圈的 mm 坐标开采样窗（收缩 60%，避开印刷方括号）
 │    每圈出两个量：ratio（二值深色占比）、ink（灰度墨迹均值 0~1）
 └─ 判定 decide()
```

### 为什么判定用「相对基线」

填涂圈里**印着 A/B/C/D 字母**，本身就有一层墨迹，实测未涂的框 `ink` 能到 **0.15~0.25**；
再叠加不同笔的深浅，**绝对阈值完全不可靠**。所以：

```
base  = min(各选项 ink)          # 本题的「空白底噪」
rel   = best.ink − base          # 真正涂出来的量
rel2  = second.ink − base
```

| 条件 | 判定 |
| --- | --- |
| `rel < 0.15` | `blank` 未填 |
| `rel2 ≥ rel − 0.15` | `multi` 多涂 / 难分 |
| `best.ink < 0.5` | `faint` 浅涂存疑 |
| 其余 | `ok` 正常 |

同时用 `ink`（灰度）而不是 `ratio`（二值）做判定：二值化会把中灰铅笔直接算成"白"，
灰度和能区分深涂与浅涂。

## 5. 实测精度

`tests/test_omr.py` 的结果（6 份合成卷 × 20 题，题目版式随机）：

| 场景 | 平均正确率 | 异常标注 |
| --- | --- | --- |
| 干净扫描（300dpi 级，无水印无畸变） | **100.0%** | 未涂题 → `blank` ✅ |
| 手机拍照模拟（透视 + 明暗渐变 + 模糊 + 噪声 + JPEG 压缩） | **100.0%** | 浅涂题 → `faint` ✅ |
| 拍照图 + 填涂阈值调低到 0.35（容错测试） | **100.0%** | — |
| 汇总统计 / 判分 / CSV | 6 份卷、每题正确率、满分 20、CSV 7 行 | ✅ |

## 6. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/` | Web 界面 |
| `POST` | `/api/template` | `multipart`：`file` = 模板 json。成功后清空已有识别结果与学生列表 |
| `GET` | `/api/template` | 返回当前模板摘要 |
| `POST` | `/api/scan` | 单张/少量：`multipart`：`files`（可多个）、`page`、`pxPerMm`、`fillMin`、`gap` |
| `POST` | `/api/batch` | **批量**：见下 |
| `POST` | `/api/roster` | `multipart`：`file` = 名单，导入后立即对已有考生重新匹配 |
| `POST` | `/api/batch/rematch` | 人工补录后重新套名单：JSON `{overrides}` 或 form `overrides` |
| `GET` | `/api/students` | 返回最近一次批量的考生列表与警告 |
| `GET` | `/api/roster.csv` | 名单对账表：考号/姓名/班级/页数/备注（含没交卷与问题项） |
| `GET` | `/api/overlay/<id>.png` | 单面卷子的校对图 |
| `POST` | `/api/stats` | JSON `{key, ids}` 或 form `key` / `ids` → 班级统计。`ids` 省略时取**最近一次识别**那批 |
| `POST` | `/api/export.csv` | form `key` / `ids` → 逐题答案 CSV（有考号时自动补上考号/姓名/班级列） |

> `ids` 的默认值是「最近一次识别的那一批」：先扫 3 张试试、再扫一个班，统计不会把两批混在一起。

`POST /api/scan` 返回：

```jsonc
{
  "results": [{
    "ok": true, "id": "a1b2c3d4e5f6", "name": "s01.png",
    "page": 0, "pxPerMm": 8.0,
    "diag": { "candidates": 7, "pxPerMm": 8.0, "expectedSidePx": 32.0 },
    "questions": [{
      "no": 1, "answer": "D", "flag": "ok",
      "best": 0.827, "second": 0.294,
      "inks":  { "A": 0.197, "B": 0.234, "C": 0.162, "D": 0.827 },
      "ratios":{ "A": 0.243, "B": 0.294, "C": 0.174, "D": 1.0 }
    }]
  }]
}
```

### `POST /api/batch` 批量上传

`multipart` 字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `files` | ✅ | 可重复。zip / 图片 / 名单文件都能丢进来 |
| `paths` | | 与 `files` **一一对应**的相对路径。浏览器选文件夹时会带 `webkitRelativePath`，用它还原目录结构；不传则退回文件名 |
| `roster` | | 名单文件。优先级高于 zip 里自带的名单 |
| `overrides` | | JSON 字符串：`{"2026010234": {"name": "张伟明", "cls": "高三(12)班"}}` |
| `pxPerMm` `fillMin` `gap` | | 同单张模式 |

返回：

```jsonc
{
  "stats": { "images": 42, "students": 21, "zips": 1 },
  "roster": { "count": 45, "source": "高三12班.csv",
              "columns": { "sid": "考号", "name": "姓名", "cls": "班级" } },
  "warnings": [
    "有 1 个考号不在名单里：2026010237",
    "名单里有 3 人没交卷（或没上传）：2026010240, …"
  ],
  "students": [{
    "sid": "2026010234", "name": "张伟明", "cls": "高三(12)班",
    "matched": true,          // true 命中名单 / false 不在名单 / null 没提供名单
    "manual": false,          // true = 靠人工补录确认的
    "issues": [],             // 待人工确认的问题；空数组=没问题
    "conflicts": [],          // 多页同一题号答案不一致的题号
    "source": "一个班/2026010234/正面.png",
    "pages": [{ "ok": true, "id": "a1b2c3d4e5f6", "page": 0, "overlay": true,
                "questions": [/* 同 /api/scan */] }],
    "answers": { "1": { "answer": "D", "flag": "ok", "best": 0.827, … } }
  }]
}
```

几个刻意的设计：

- **`answers` 的键是字符串**（过了 JSON），前端取值要按 `'1'` 而不是 `1`。
- **一面出错不作废整份**：某一面识别失败时该面 `ok:false` 并进 `issues`，其余面的答案照常保留。
- **页序越界一定报错**，不会被悄悄夹到最后一页 —— 否则「多传了一页」会拿错的模板面采样，
  答案看着正常但是错的，这是阅卷工具里最坏的失败方式。
- **补录姓名后 `matched` 变 `true`、`issues` 清空**，但保留 `manual: true` 让界面区分来源，
  同时对应的 warning 消失 —— 问题是真的解决了，不是被掩盖。
- 批量是「一个班一次」的操作：**会整批替换**上一次的结果集。


| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `pxPerMm` | `8.0` | 矫正后的输出分辨率。8 px/mm ≈ 203dpi，足够采样且省内存 |
| `fillMin` | `0.5` | 低于此墨迹值判为「浅涂存疑」；铅笔特别淡可下调 |
| `gap` | `0.15` | 最优与次优选项的间距阈值，小于等于则判「多涂/难分」 |
| `page` | `0` | 模板第几面（双面卷分面上传时用） |

## 7. 阅卷模板格式（`asb-omr/1`）

```jsonc
{
  "format": "asb-omr/1",
  "paper": { "size": "A4", "orientation": "portrait", "w": 210, "h": 297 },
  "marks": { "shape": "square", "size": 4 },        // 定位点形状与边长（mm）
  "pages": [{
    "index": 0,
    "marks": [ { "pos": "tl", "x": 10.0, "y": 10.0 }, /* tr, br, bl */ ],
    "questions": [{
      "no": 1,
      "x": 30.0, "y": 45.0,
      "options": [ { "opt": "A", "x": 34.0, "y": 45.0, "w": 6.0, "h": 6.0 } ]
    }]
  }],
  "questionCount": 20
}
```

所有坐标都是**相对页面左上角的毫米值**。`marks[].size` 同时用于估算定位点在扫描图里的期望像素面积。

## 9. 排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `只找到 N 个定位点候选（需要 4 个）` | 扫描件被裁掉了四角，或定位点印得太浅/太小。重新完整扫描，别裁剪边缘 |
| `定位点构成的四边形过小` | 误检（把页面里的黑块当成定位点）。确认扫描件是完整页面 |
| 全题 `multi` | 模板与卷子不是同一份，或坐标整体偏移。核对模板文件名与卷子版本 |
| 全题 `blank` | 矫正后的网格对不上。用 `tests/diag1.py` 看矫正图 |
| 铅笔作答大量 `faint` | 把 `fillMin` 下调到 `0.35` 左右 |
| `没有可识别的填涂圈` | 卷子里的选择题是手写模式，需在制卡端改成填涂圈模式 |
| 批量时「未能从文件名解析出考号」 | 文件名/目录名里没有 4~20 位数字串。按 §3.3 改名，或在待确认队列里补录 |
| 批量时「同一考号出现在多个目录」 | 重复上传或撞号。同一目录下多文件才是正常多页 |
| 批量时「页序号 N 超出模板范围」 | 卷子面数多于模板面数（多扫了一页，或者用了错的模板）。**这条必须处理，别忽略** |
| 名单里有人没匹配上 | 检查名单里的考号是数字还是带前缀字母（如 `A2026010234`）—— 目前取的是数字串 |
| 名单读出来乱码 | 名单是 GBK 也能读，但如果表头是自定义写法（如「学生编号」）会识别不到，按 §3.3 改表头 |
| 一次传一个班很慢 | 单张约 0.3~0.5s（CPU），50 人×2 面约半分钟。`pxPerMm` 降到 6 可以再快些 |

## 10. 许可

与制卡端一致。
