# 答题卡扫描识别服务（scanner）

把学生作答后的答题卡（扫描仪 300dpi 或手机拍照）转成结构化答案，并按题汇总班级情况。
**纯 OpenCV / NumPy 实现，不下载任何模型，CPU 即可运行，可完全离线。**

本服务是 [answer-sheet-builder](../) 仓库的子目录。制卡端负责排版并导出 `阅卷模板`
（含每个填涂圈的毫米坐标），本服务只认模板 + 图像。

---

## 1. 它能做什么

| 能力 | 说明 |
| --- | --- |
| 选择题识别 | 定位四角定位点 → 透视矫正 → 按模板坐标采样填涂圈 → 判定 A/B/C/D |
| 双输入源 | 扫描仪 300dpi 平面图、手机斜拍图（自带明暗归一化 + 透视矫正） |
| 异常标注 | 每题给出状态：`ok` 正常 / `faint` 浅涂存疑 / `multi` 多涂或难分 / `blank` 未填 |
| **卷面考号** | **从答题卡上的考号填涂区直接读出考号 —— 不用给学生发二维码，也不用把文件改名叫考号** |
| 校对图 | 每份卷子回吐一张叠加图，绿圈=已选、红圈=存疑、灰圈=未选，圈旁标注墨迹值；考号选中的那一格也会被圈出来 |
| **批量上传** | **一次丢一个班：zip 压缩包 / 整个文件夹 / 一堆散图，自动归组、多页自动合并** |
| **名单匹配** | **上传 `考号,姓名,班级` 名单（CSV/TSV，GBK 也认），自动贴上姓名班级、列出待确认项** |
| 班级统计 | 每题各选项分布 + 正确率；每份卷子得分；一键导出 CSV |
| Web 界面 | 上传模板 → 拖入扫描件 → 看结果 → 出统计，全在浏览器里 |

## 2. 快速开始

### 2.1 Docker（推荐）

```bash
cd scanner
docker compose up -d --build
# 打开 http://<主机IP>:8081
```

默认 `8081` 端口，叠加图落在 `./data/`（compose 已 bind 到容器 `/srv/data`）。

> **首次启动要先建账号**：库里一个用户都没有时，打开页面会进「创建管理员」而不是登录页
> —— **服务不内置任何默认口令**（默认口令 = 全网都知道的口令）。设置好管理员账号后，
> 后续所有人用各自账号登录，角色分三种：**管理员**（能管用户）/ **老师**（能上传识别、改结果）/
> **只读**（只能看）。会话存在服务端 SQLite，能改口令踢掉别处登录、能退出即时失效。

构建默认走清华 PyPI 源，海外或私有源覆盖：

```bash
PIP_INDEX=https://pypi.org/simple docker compose up -d --build
```

### 2.2 本地直跑（开发调试）

```bash
pip install -r requirements.txt
python -m app.server          # http://127.0.0.1:8081
```

### 2.3 自检

```bash
# 全部离线跑，不需要服务、不需要网络、不需要任何外部素材
python tests/test_omr.py        # 识别核心：定位 / 采样 / 判定 / 统计判分
python tests/test_batch.py      # 批量逻辑：路径解析 / zip 解包 / 归组 / 名单匹配 / 页序
python tests/test_service.py    # 服务层：用 Flask 测试客户端直接打接口，不用起服务

# 服务级集成：需要先把服务跑起来
docker compose up -d            # 或 python -m app.server
python tests/e2e_service.py                     # 默认 http://127.0.0.1:8081
BASE=http://192.168.1.10:8081 python tests/e2e_service.py
```

`test_omr.py` 用 `tests/fixtures/` 里 6 份**由真实制卡端渲染出来**的答题卡，跑识别率、
存疑标注与汇总判分；手机拍照图是运行时现场合成的（透视 + 明暗 + 模糊 + 噪声 + JPEG）。
`test_service.py` 把 zip、名单、补录、越界页序这些接线问题在**部署之前**就拦住。
`e2e_service.py` 则对着真容器走一遍完整业务流（含批量上传），容器里是 opencv 4.9。

> 改动识别相关代码后，三份都要跑 —— 尤其 `e2e_service.py`：一个返回 200 的健康探针
> 只能证明进程活着。

素材里刻意埋了两个边界情况：**第 3 题未涂**（应判 `blank`）、**第 8 题用中灰浅涂**（应判 `faint`）——
这两条是判定逻辑最容易退化的地方。素材怎么重新生成见 [../dev/README.md](../dev/README.md)。

## 3. 使用流程

### 3.1 批量模式（一个班，推荐）

```
┌──────────────────┐   ┌──────────────────┐   ┌───────────────────────────────┐
│ 扫描仪 / 手机     │   │ 打成 zip，或直接  │   │ scanner 服务                   │
│ 扫出 PNG / JPG    │──▶│ 选整个文件夹      │──▶│ 拖入 zip / 文件夹 + 名单(CSV)   │
│                  │   │ 改名可选          │   │ → 从卷面读考号 → 归组 → 匹配     │
└──────────────────┘   └──────────────────┘   └───────────────────────────────┘
                                                       │
                        ┌──────────────────────────────┴──────────────────┐
                        ▼                                                 ▼
              待人工确认队列(补录姓名/班级)                    成绩 CSV（带考号/姓名/班级）
```

1. **制卡端导出模板**并在服务里上传（同 3.2 第 1~2 步）。模板必须带考号填涂区
   （制卡端「考生信息栏」里勾上**考号填涂区**），否则卷面上没有考号可读。
2. **整理扫描件 —— 怎么放都行**：学生涂了考号，服务自己会从卷面上读出来。
   文件名/目录名里带考号当然更好（能互相印证，也方便你溯源），参考资料见 3.3。
3. **拖入** `② 批量上传` 区域：可以直接拖 zip、拖散图，也可以拖**整个文件夹**（浏览器会自动递归）。
4. **选名单**（可选）：`考号,姓名,班级` 的 CSV/TSV。名单也可以直接放进 zip 里，服务会自己找。
   有了名单还能多做两件事：**把只差一位数字的考号认出来**、**把卷面上漏涂的那一位补全**。
5. **开始批量识别**。页面按考生一位一张卡，显示姓名班级、答案摘要、每面校对图缩略图（点开看原生分辨率）。
6. **处理待确认队列**：考号不在名单里、文件名与卷面不一致、卷面有缺位、跨目录重复、页序异常等会列出来，
   补上姓名/班级后点「重新套用」—— 只改标注，**不会重新识别**，识别出来的答案不会被改动。
7. **出统计 / 导出**：填标准答案 → 统计；`导出成绩 CSV` 带考号/姓名/班级列，`导出名单对账 CSV` 用来核对谁没交
   （含「考号来源」一列，说明这个考号是卷面读到的还是文件名里的）。

### 3.2 单张模式（调参、排查用）

1. **制卡端导出模板**：答题卡生成器工具栏点 `🎯 阅卷模板`，得到一个
   `asb-omr-template-A4-20q-20260925-0140.json` 这样的文件。
   > 前提：卷子里有**填涂圈模式**的选择题（不是手写作答模式），否则会提示「没有可识别的填涂圈」。
2. **上传模板**：扫描服务的第 1 步选这个 json，页面会显示题数与面数。
3. **拖入扫描图**：一次可以传多份，逐份识别。
4. **看结果**：左侧是校对图（叠加图），右侧是每题判定表，存疑题带红色标记。
5. **填标准答案**（可选）：`1A 2B 3C` 或 `ABCD` 都行，然后出统计——每题正确率、每份得分。
6. **导出 CSV**：逐题答案矩阵 + 得分列。

> **一个模板 = 一面卷子。** 双面卷请把每一面都扫出来，并在文件名里写清页序
> （`正面.png` / `反面.png` / `_1` `_2` / `第2页`）；批量模式下服务会自动按页序合并。

### 3.3 这份卷子是谁的：卷面考号优先，文件名兜底

**第一优先是卷面上涂的考号**（考生信息栏里的考号填涂区）。它必须在识别之后才拿得到，
所以分组是**识别完再校正**的：先按文件名粗分，认出考号之后重算。

两种来源的关系：

| 情况 | 处理 |
| --- | --- |
| 文件名里没有考号，卷面读到 | **按卷面归组** —— 散着传的多页也会被并成一份 ✅ 推荐 |
| 文件名里的考号与卷面一致 | 互证，标为「文件名 + 卷面（一致）」 |
| 文件名里的考号与卷面**不一致** | **保持原样不动**，两边都报出来让人确认 —— 把卷子记错名字是不可逆的错 |
| 卷面有 1~2 位没涂出来 | 名单里**有且只有**一个人符合 → 自动补全；否则留着缺位等人填 |
| 卷面缺位太多 / 同一份卷子两页读出不同考号 | 不猜，进待确认队列 |

「卷面优先」在哪些情况下成立，取决于文件名里的数字**像不像**一个考号：

| 文件名 | 里面那串数字算考号吗 |
| --- | --- |
| `2026010234/正面.png` `2026010234_1.png` `张伟明-2026010234.png` | ✅ 算 —— 有人特意写的 |
| `IMG_0001.jpg` `DSC_0123.png` `扫描件_20240925_1030.png` | ❌ 不算 —— 序号或时间戳，改用卷面考号 |
| 名单里正好有 `0001` 这个人 | ✅ 算 —— 命名习惯不一致时以名单为准 |

> 这条区分很要紧。如果把 `IMG_0001` 里的 `0001` 当成考号，系统会认为「文件名说 0001、卷面说
> 2026010234」而拒绝归组 —— 越是随手命名的人越用不了，正好和「不想改名」的初衷相反。

**考号解析规则**（4~20 位数字，目录名优先于文件名）：

| 形式 | 解析结果 |
| --- | --- |
| `2026010234/正面.png` + `2026010234/反面.png` | 考号 `2026010234`，两面自动合并 ✅ 最省事 |
| `2026010234_1.png` `2026010234_2.png` | 考号 `2026010234`，页序 1、2 |
| `张伟明-2026010234.png` | 考号取**最后一段**数字串 |
| `20xx/2026010234.png` | 目录里没有数字 → 回退到文件名取考号 |
| `随机名.png` | 解析不出考号 → 先用文件名当标识；卷面读到考号就会自动改用卷面的 |

页序提示认这些写法（大小写不敏感）：`正面/反面`、`前页/后页`、`首页/背页`、`上/下`、
`front/back`、`f/p1`、`r/p2`、`第2页`，以及 `_1` `_2` 这样的裸数字（按「第 N 页」，上限 20 页）。
裸数字在 1~20 之外的不当页号，避免把年份当成页码。

> **多面模板 + 没有页序提示**会在结果页顶部给一条警告：页码是我们按上传顺序猜的，
> 拿错面的坐标去采样会得到「看着正常但其实错的」答案，所以这件事必须说出来。

打包时自动忽略：`__MACOSX/`、`._*` 资源分叉文件、`.DS_Store`、`Thumbs.db`、`.git/`。
嵌套 zip 也会被展开。

## 4. 识别流程（`app/omr.py`）

```
原图
 ├─ 灰度化 → 形态学背景除法归一化（压掉手机拍照的明暗渐变）
 │    ★ 背景按 1/4 分辨率估计再插值回来（见下）
 ├─ 自适应二值化 → 轮廓筛选
 │    面积 ∈ [0.25·期望, 2.2·期望]，长宽比 0.55~1.8，
 │    实心度 ≥ 0.30，且必须落在页面外侧 22% 边带内
 ├─ 候选点按 x+y / x-y 取极值 → tl, tr, br, bl
 ├─ 自检：四点四边形面积 ≥ 0.35·图幅，否则判为误检
 ├─ getPerspectiveTransform → 矫正到与模板一致的 mm 网格
 │    ★ 目标点是「模板里的定位点坐标」，不是纸张四角（差一个内缩量）
 ├─ 按模板每个填涂圈的 mm 坐标开采样窗（收缩 60%，避开印刷方括号）
 │    每圈出两个量：ratio（二值深色占比）、ink（灰度墨迹均值 0~1）
 ├─ 判定 decide()          → 每题答案 + 状态
 └─ 判定 decode_sid()      → 考号逐位数字 + 状态
     两条路共用同一个 _prep()（归一化 + 二值化），阈值完全一致 ——
     否则「选择题读得准、考号读不准」这种差异没法解释
```

### 为什么背景要在 1/4 分辨率上估

原来 `_lighting_normalize` 直接对原图（一台 A4@400dpi 扫描件约 14M 像素）做
**159×159 椭圆闭运算**，单独一步就要 **900ms** —— 而整条识别里其它部分加起来才 100ms 出头，
在容器里更慢（实测单张 **13.2s**，一个班 100 张要 20 多分钟）。

背景是一层**低频平滑场**，把它降到 1/4 分辨率再算、然后插值回来，物理邻域完全一致
（核尺寸按原图算完再换算到小图上，避免小图上 `max(15, …)` 下限引入相对更大的核）。
实测归一化结果与原实现**逐像素最大差 9/255**（P99 = 6），识别率不变，单张 **13.2s → 0.37s**。

### 为什么判定用「相对基线」

填涂圈里**印着 A/B/C/D 字母**，本身就有一层墨迹，实测未涂的框 `ink` 能到 **0.15~0.25**；
再叠加不同笔的深浅，**绝对阈值完全不可靠**。所以：

```
base  = min(各选项 ink)          # 本题的「空白底噪」
rel   = best.ink − base          # 真正涂出来的量
rel2  = second.ink − base
```

| 条件 | 判定 |
| --- | --- |
| `rel < 0.15` | `blank` 未填 |
| `rel2 ≥ rel − 0.15` **且** `rel2 ≥ 0.2` | `multi` 多涂 / 难分 |
| `best.ink < 0.5` | `faint` 浅涂存疑 |
| 其余 | `ok` 正常 |

> `rel2 ≥ 0.2` 这个附加条件是必需的。**四个印刷字母之间的 ink 极差就有 0.08 左右**
> （实测一道空白题是 0.079），只看 `rel2 ≥ rel − gap` 时，浅涂题的次优往往是某个印刷字母：
> 「A 涂得太轻」（ink 0.388）的次优是字母 D（0.243），`rel2` 只比门槛高 **0.005** ——
> 于是一道浅涂题被报成「A 和 D 都涂了」。次优必须真的是墨迹才叫多选，否则退回 `faint`
> （两个状态都会进复核队列，但 `faint` 指向的是正确答案）。

同时用 `ink`（灰度）而不是 `ratio`（二值）做判定：二值化会把中灰铅笔直接算成"白"，
灰度和能区分深涂与浅涂。

### 考号为什么也用「相对基线」

考号每一位是一列 10 个格子，**列内只有一个是涂的**，其余 9 格是空白（底噪 0.15~0.25），
所以相对差比选择题还明显（涂实是 0.83）：

| 条件 | 判定 | 含义 |
| --- | --- | --- |
| `rel < 0.15` | `blank` | 这一位没涂 → 输出 `?` 占位，保持位数对齐 |
| `rel2 ≥ rel − 0.12` 且 `rel2 ≥ 0.2` | `doubt` | 一列涂了两个数字 |
| `best.ink < 0.5` | `faint` | 涂了但很浅（中灰约 0.39） |
| 其余 | `ok` | 干净利落 |

`?` 意味着这**一整个数字**没读出来 —— 比读错一位更危险（会把卷子归到别人名下），
所以只要出现 `?` 或任何非 `ok` 位，这份卷子的考号就会被标出来而不是默默采用。

## 5. 实测精度

`tests/test_omr.py` 的结果（6 份合成卷 × 20 题 + 3 份边界素材，题目版式随机）：

| 场景 | 答案 | 卷面考号 | 异常标注 |
| --- | --- | --- | --- |
| 干净扫描（300dpi 级，无水印无畸变） | **100.0%** | **100.0%** | 未涂 → `blank`、浅涂 → `faint`、涂两个 → `multi` ✅ |
| 手机拍照模拟（透视 + 明暗渐变 + 模糊 + 噪声 + JPEG 压缩） | **100.0%** | **100.0%** | 三处存疑没有一处被当成正常作答 ✅ |
| 拍照图 + 填涂阈值调低到 0.4（容错测试） | **100.0%** | **100.0%** | — |
| 汇总统计 / 判分 / CSV | 6 份卷、每题正确率、满分 20、CSV 7 行 | — | ✅ |

考号的边界素材各钉住一种「读不准时要说读不准」：

| 素材 | 卷面状态 | 期望结果 |
| --- | --- | --- |
| `x1-blank.png` | 第 3 位整格漏涂 | 读出 `20?6010234`，第 3 位 `blank`，`ok=False` |
| `x2-light.png` | 第 5 位浅涂（中灰） | 读出完整考号，第 5 位 `faint`（ink 0.388） |
| `x3-multi.png` | 第 2 位涂了两个数字 | 第 2 位 `doubt`（两格都是 0.827），候选 `{0,5}` |

> 识别不出来不可怕，**读错了却报 `ok`** 才可怕 —— 那等于把卷子静默地归给别人。
> 所以这三张素材断言的是「第几位、什么状态」，而不是「大概读对了」。

### 速度

在本地 Ubuntu + Docker（2 核）上实测，单张 A4@400dpi 扫描件：

| 操作 | 耗时 |
| --- | --- |
| 单张识别（`/api/scan`，含上传与 JSON 回传） | **0.37 s** |
| 批量 6 张（zip 0.8MB，`/api/batch`） | 2.2 s（每张 0.37 s） |
| 一个班 50 人 × 2 面 = 100 张 | **约 40 秒** |

> 这里曾经是 13.2 s/张（一个班 20 多分钟），瓶颈是背景归一化那一步 —— 见 §4。

## 6. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/` | Web 界面 |
| `POST` | `/api/template` | `multipart`：`file` = 模板 json。成功后清空已有识别结果与学生列表 |
| `GET` | `/api/template` | 返回当前模板摘要 |
| `POST` | `/api/scan` | 单张/少量：`multipart`：`files`（可多个）、`page`、`pxPerMm`、`fillMin`、`gap` |
| `POST` | `/api/batch` | **批量**：见下 |
| `POST` | `/api/roster` | `multipart`：`file` = 名单，导入后立即对已有考生重新匹配 |
| `POST` | `/api/batch/rematch` | 人工补录后重新套名单：JSON `{overrides}` 或 form `overrides` |
| `GET` | `/api/students` | 返回最近一次批量的考生列表与警告 |
| `GET` | `/api/roster.csv` | 名单对账表：考号/姓名/班级/考号来源/页数/说明/备注（含没交卷与问题项） |
| `GET` | `/api/overlay/<id>.png` | 单面卷子的校对图 |
| `POST` | `/api/stats` | JSON `{key, ids}` 或 form `key` / `ids` → 班级统计。`ids` 省略时取**最近一次识别**那批 |
| `POST` | `/api/export.csv` | form `key` / `ids` → 逐题答案 CSV（有考号时自动补上考号/姓名/班级列） |

> `ids` 的默认值是「最近一次识别的那一批」：先扫 3 张试试、再扫一个班，统计不会把两批混在一起。

`POST /api/scan` 返回：

```jsonc
{
  "results": [{
    "ok": true, "id": "a1b2c3d4e5f6", "name": "s01.png",
    "page": 0, "pxPerMm": 8.0,
    "diag": { "candidates": 7, "pxPerMm": 8.0, "expectedSidePx": 32.0 },
    "sid": { "text": "2026010234", "digits": 10, "ok": true, "filled": 10,
             "flags": ["ok", "ok", …] },        // 卷面考号；模板没有这一块时为 null
    "questions": [{
      "no": 1, "answer": "D", "flag": "ok",
      "best": 0.827, "second": 0.294,
      "inks":  { "A": 0.197, "B": 0.234, "C": 0.162, "D": 0.827 },
      "ratios":{ "A": 0.243, "B": 0.294, "C": 0.174, "D": 1.0 }
    }]
  }]
}
```

> `sid.positions`（逐位的坐标与墨迹值）只在服务端用来看校对图，不发给浏览器。

### `POST /api/batch` 批量上传

`multipart` 字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `files` | ✅ | 可重复。zip / 图片 / 名单文件都能丢进来 |
| `paths` | | 与 `files` **一一对应**的相对路径。浏览器选文件夹时会带 `webkitRelativePath`，用它还原目录结构；不传则退回文件名 |
| `roster` | | 名单文件。优先级高于 zip 里自带的名单 |
| `overrides` | | JSON 字符串：`{"2026010234": {"name": "张伟明", "cls": "高三(12)班"}}` |
| `pxPerMm` `fillMin` `gap` | | 同单张模式 |

返回：

```jsonc
{
  "stats": { "images": 42, "students": 21, "zips": 1 },
  "roster": { "count": 45, "source": "高三12班.csv",
              "columns": { "sid": "考号", "name": "姓名", "cls": "班级" } },
  "warnings": [
    "有 1 个考号不在名单里：2026010237",
    "名单里有 3 人没交卷（或没上传）：2026010240, …"
  ],
  "students": [{
    "sid": "2026010234", "name": "张伟明", "cls": "高三(12)班",
    "matched": true,          // true 命中名单 / false 不在名单 / null 没提供名单
    "manual": false,          // true = 靠人工补录确认的
    "sidSource": "both",      // 考号来源，见下表
    "fileSid": "2026010234",  // 从文件名解析出来的（可能是 IMG_0001 里的 "0001"）
    "fileName": "正面.png",
    "sheetSid": "2026010234", // 卷面读到的；读不出来或两页打架时为 null
    "note": "…",              // 需要解释一句时才有，比如「按卷面涂的 X 归组」
    "sidSuggest": [],         // 唯一命中时给一个「只差一位」的考号
    "issues": [],             // 待人工确认的问题；空数组=没问题
    "conflicts": [],          // 多页同一题号答案不一致的题号
    "source": "一个班/2026010234/正面.png",
    "pages": [{ "ok": true, "id": "a1b2c3d4e5f6", "page": 0, "overlay": true,
                "hinted": true,              // 页码是文件名提示的，还是按顺序猜的
                "sid": { "text": "2026010234", … },
                "questions": [/* 同 /api/scan */] }],
    "answers": { "1": { "answer": "D", "flag": "ok", "best": 0.827, … } }
  }]
}
```

`sidSource` 的取值：

| 值 | 含义 | 要不要人工看 |
| --- | --- | --- |
| `file` | 文件名里有考号，卷面没读到（老模板没有考号区） | 页数 > 1 时留意 |
| `file-stem` | 文件名里连考号都没有，拿文件名当标识 | 是 |
| `both` | 文件名与卷面一致 | 否 |
| `sheet` | 文件名没给考号，按卷面涂的归组 | 否 |
| `roster` | 卷面有缺位，名单里唯一符合 → 补全 | 否（`note` 里会说明） |
| `conflict` | 文件名与卷面**不一致** | 是（已按文件名归组） |
| `sheet-partial` | 卷面有缺位且名单里认不出 | 是 |

几个刻意的设计：

- **`answers` 的键是字符串**（过了 JSON），前端取值要按 `'1'` 而不是 `1`。
- **一面出错不作废整份**：某一面识别失败时该面 `ok:false` 并进 `issues`，其余面的答案照常保留。
- **页序越界一定报错**，不会被悄悄夹到最后一页 —— 否则「多传了一页」会拿错的模板面采样，
  答案看着正常但是错的，这是阅卷工具里最坏的失败方式。
- **补录姓名后 `matched` 变 `true`、`issues` 清空**，但保留 `manual: true` 让界面区分来源，
  同时对应的 warning 消失 —— 问题是真的解决了，不是被掩盖。
- 批量是「一个班一次」的操作：**会整批替换**上一次的结果集。


| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `pxPerMm` | `8.0` | 矫正后的输出分辨率。8 px/mm ≈ 203dpi，足够采样且省内存 |
| `fillMin` | `0.5` | 低于此墨迹值判为「浅涂存疑」；铅笔特别淡可下调 |
| `gap` | `0.15` | 最优与次优选项的间距阈值，小于等于则判「多涂/难分」 |
| `page` | `0` | 模板第几面（双面卷分面上传时用） |

## 7. 阅卷模板格式

两个版本，服务**两个都认**（老模板不必重新导出，只是拿不到卷面考号）：

| 版本 | 内容 |
| --- | --- |
| `asb-omr/1` | 只有选择题填涂圈 |
| `asb-omr/2` | 另有考生信息栏的**考号填涂区** `pages[].sid` |

```jsonc
{
  "format": "asb-omr/2",
  "paper": { "size": "A4", "orientation": "portrait", "w": 210, "h": 297 },
  "marks": { "style": "square", "size": 4 },        // 定位点形状与边长（mm）
  "sid": { "digits": 10, "onPages": [0] },          // v1 没有这块；没导出考号区时为 null
  "pages": [{
    "index": 0,
    "marks": [ { "pos": "tl", "x": 10.0, "y": 10.0 }, /* tr, br, bl */ ],
    "sid": {                                        // 卷面考号填涂区（v2 新增）
      "digits": 10,
      "positions": [{
        "pos": 1,                                   // 第几位（1 起）
        "bubbles": [ { "digit": "0", "x": 34.0, "y": 45.0, "w": 4.0, "h": 4.0 } ]
      }]
    },
    "questions": [{
      "no": 1,
      "x": 30.0, "y": 45.0,
      "options": [ { "opt": "A", "x": 34.0, "y": 45.0, "w": 6.0, "h": 6.0 } ]
    }]
  }],
  "questionCount": 20
}
```

所有坐标都是**相对页面左上角的毫米值**。`marks[].size` 同时用于估算定位点在扫描图里的期望像素面积。

一份**只有考号区、没有选择题**的卷子也能导出模板（用于纯信息卡），
`questionCount` 会是 0、`sid` 有值 —— 导出按钮只要求「有填涂圈或有考号区」其中之一。

## 9. 排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `只找到 N 个定位点候选（需要 4 个）` | 扫描件被裁掉了四角，或定位点印得太浅/太小。重新完整扫描，别裁剪边缘 |
| `定位点构成的四边形过小` | 误检（把页面里的黑块当成定位点）。确认扫描件是完整页面 |
| 全题 `multi` | 模板与卷子不是同一份，或坐标整体偏移。核对模板文件名与卷子版本 |
| 全题 `blank` | 矫正后的网格对不上。用 `tests/diag1.py` 看矫正图 |
| 铅笔作答大量 `faint` | 把 `fillMin` 下调到 `0.35` 左右 |
| `没有可识别的填涂圈` | 卷子里的选择题是手写模式，需在制卡端改成填涂圈模式 |
| 批量时「未能从文件名解析出考号」 | 文件名/目录名里没有 4~20 位数字串，且**卷面也没读到考号**。按 §3.3 改名，或在待确认队列里补录 |
| 批量时「同一考号出现在多个目录」 | 重复上传或撞号。同一目录下多文件才是正常多页 |
| 批量时「页序号 N 超出模板范围」 | 卷子面数多于模板面数（多扫了一页，或者用了错的模板）。**这条必须处理，别忽略** |
| 批量时「文件名里的考号（X）和卷面涂的（Y）不一致」 | 已按文件名归组、**没有**擅自改动。确认是学生涂错还是文件命名错了 |
| 批量时「卷面考号有 N 位没涂出来」 | 学生那几位整格没涂。名单里唯一符合会自动补全，否则在待确认队列里补录 |
| 批量时「文件名里的数字不太像考号…N 页被归到同一个人」 | `IMG_0001` 这类名字 + 卷面没读到考号，多页归谁全靠猜。改用带考号的模板，或给文件改名 |
| 批量时「有 N 张图找不到页序提示」 | 多面模板 + 文件名里没写页序。**页码是按上传顺序猜的**，可能在拿错面的坐标采样 —— 按 §3.3 补页序后重传 |
| 考号读成 `20?6010234` 这种带 `?` 的 | 那一位整格漏涂。`?` 表示一个完整数字没读出来，比读错一位更该人工确认 |
| 卷面考号全是 `faint` | 学生用铅笔涂得太轻。可把 `fillMin` 降到 `0.35` 再看 |
| 名单里有人没匹配上 | 检查名单里的考号是数字还是带前缀字母（如 `A2026010234`）—— 目前取的是数字串 |
| 名单读出来乱码 | 名单是 GBK 也能读，但如果表头是自定义写法（如「学生编号」）会识别不到，按 §3.3 改表头 |
| 一次传一个班慢不慢 | 单张约 **0.37s**（2 核容器实测），50 人×2 面约 40 秒。再想快可把 `pxPerMm` 降到 6 |

## 11. 账号、角色与数据持久化

### 11.1 登录与角色

服务现在**需要登录**。所有 `/api/*` 默认拒绝，白名单只放四个公开接口：

| 接口 | 作用 |
| --- | --- |
| `GET /api/health` | 探活 + 初始化状态（docker 健康检查打这个，不是 `/api/template`） |
| `GET /api/me` | 当前登录身份 / 是否还没初始化 |
| `POST /api/setup` | 库里一个用户都没有时，创建第一个管理员（之后调用返回 403） |
| `POST /api/login` | 登录，下发会话 cookie（`asb_sid`，HttpOnly + SameSite=Lax） |

角色只判定**动作**不判定数据：

| 角色 | 能改数据（上传识别 / 改结果 / 删考试） | 能管用户 |
| --- | --- | --- |
| 管理员 `admin` | ✅ | ✅ |
| 老师 `teacher` | ✅ | ❌ |
| 只读 `viewer` | ❌（写操作返回 403） | ❌ |

口令只存 `pbkdf2_sha256`（20 万次迭代 + 盐），用标准库 `hashlib` 实现，不引第三方依赖。
**会话存在服务端 SQLite**：改完口令会吊销自己所有会话、退出登录会真的删掉会话记录（不是只清 cookie）。
管理界面（`⑤ 账号管理`，仅管理员可见）能建账号、改角色、重置口令、删除账号；
**最后一个管理员既不能降级也不能删除** —— 否则就没人能管用户了。

### 11.2 数据持久化（考试为单元）

去掉了原来的内存 `STATE`。每个请求都按 `exam_id` 从 `data/asb.db` 读写：

- **重启安全**：模板 / 名单 / 标准答案 / 考生 / 扫描结果全部进库，服务重启或容器重建（只要 `data/` 还在）结果都还在。
- **并发安全**：两个老师同时用，各自的结果按考试隔离，不会互相冲掉。
- 多考试：所有人看得到所有考试，角色只决定能不能改 / 能不能管；顶部下拉切换考试，最近一次操作的考试会被记住。

> **一个隐蔽的坑**：判分是按「题号」查答案的，题号在内存里是 `int`，但 JSON 只认字符串键。
> 如果把整个考生字典（含 `answers`）当 JSON blob 存进去再读回来，没归一化的话 `answers` 的键全变成字符串，
> 判分按 `int` 查就全查不到 → **全班 0 分**。持久化层统一在读写时做「题号键 ↔ 字符串」的归一化，
> 并在 `test_store.py` / `test_service.py` 里钉住「存进去再读回来分还是对的」这条不变量。

环境变量（均可选）：`ASB_DB` 改库路径、`ASB_COOKIE_SECURE=1` 走 HTTPS 时给 cookie 加 `Secure`、
`PORT` 改监听端口。
